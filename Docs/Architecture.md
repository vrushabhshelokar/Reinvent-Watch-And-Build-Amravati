# Technical Architecture
## Reinvent Watch And Build — Amravati

## 1. Stack

- Next.js with App Router
- TypeScript
- Tailwind CSS
- React
- Lucide React for icons, if needed
- Motion for React only if subtle animation adds value
- Luma for registration
- Privacy-conscious web analytics provider, selected before implementation
- Vercel for hosting and deployment
- GitHub for version control and pull-request workflow

Use current stable compatible package versions at implementation time. Commit the lockfile.

## 2. Architecture principles

1. Prefer static rendering for the event landing page because most content is known before a visitor arrives.
2. Keep the page server-rendered/static by default. Use client components only for interactions such as mobile navigation, FAQ accordions, and analytics event dispatch.
3. No database or custom backend is needed for the initial release.
4. Keep event-specific content in typed data modules so dates, agenda items, organizers, partners, and the Luma URL can be changed centrally.
5. Never put secret keys in client-side environment variables. A public analytics ID may be public if the provider documents it as such.
6. Use the official Luma event URL; do not create a second registration system.

## 4. Page composition

`src/app/page.tsx` composes the page in this order:
1. SiteHeader
2. HeroSection
3. EventInfoStrip
4. BenefitsSection
5. AboutSection
6. AgendaSection
7. CommunitySection
8. PastEventsSection
9. OrganizersSection
10. VenueFaqSection
11. RegistrationCTA
12. SiteFooter

`StickyRegisterBar` is a persistent responsive utility, not an extra content section. It may be hidden on desktop or when the main CTA is already prominent, based on usability testing.

## 5. Typed event data

Keep unresolved values explicit rather than silently inventing defaults.

```ts
export const event = {
  name: "Reinvent Watch And Build",
  locationLabel: "Amravati",
  tagline: "Watch. Learn. Build. Connect.",
  entryFee: 0,
  date: "[CONFIRM: EVENT_DATE]",
  startTime: "[CONFIRM: EVENT_START_TIME]",
  endTime: "[CONFIRM: EVENT_END_TIME]",
  timeZone: "Asia/Kolkata",
  venueName: "[CONFIRM: VENUE_NAME]",
  venueAddress: "[CONFIRM: FULL_VENUE_ADDRESS]",
  lumaUrl: "[CONFIRM: LUMA_REGISTRATION_URL]",
  productionUrl: "[CONFIRM: PRODUCTION_DOMAIN]",
} as const;
```

Add a build-time or pre-release validation that fails if launch-critical placeholder strings remain in production configuration. Do not deploy a site that exposes these literal placeholders.

## 6. Luma integration

- All CTA components consume one shared `lumaUrl` value.
- Validate that the configured URL uses HTTPS and points to the intended event.
- Use a descriptive accessible link name such as “Register for free on Luma”.
- Add `target="_blank"` only if desired; if used, include `rel="noopener noreferrer"`.
- Track CTA click events before navigation only using the selected provider's supported API. Do not block or materially delay navigation.
- Treat Luma as the source of truth for registration status and completed registration reporting.

## 7. Analytics and visitor count

Choose one analytics provider and document its privacy behavior. Track page views and named events such as `registration_cta_click` with a non-sensitive parameter for placement (`hero`, `agenda`, `final_cta`, `sticky_mobile`).

Do not send names, email addresses, registration form values, or other personal data to analytics. Avoid double-counting events when components re-render. If displaying a public counter, define whether it represents page views, sessions, or estimated unique visitors and use a supported persistent counter/analytics API. A browser-local counter is not a shared visitor count and must not be presented as one.

## 8. Styling and performance

- Use Tailwind design tokens and CSS variables for colors, spacing, radii, and typography.
- Prefer CSS transitions over a large animation dependency.
- Use `next/image` for optimized images where appropriate.
- Provide explicit image dimensions/aspect ratios to reduce layout shift.
- Avoid loading unnecessary third-party scripts before consent or before needed, subject to the selected analytics provider's requirements.
- Respect `prefers-reduced-motion`.

## 9. Deployment and environment

- Deploy production builds through Vercel connected to GitHub.
- Use preview deployments for pull requests.
- Store only required public IDs in `NEXT_PUBLIC_*` variables.
- Keep any private API keys in server-only environment variables if a future integration genuinely requires them.
- Configure the production canonical URL only after the domain is known.
